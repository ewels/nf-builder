# 0035. Build the registry snapshot in a scheduled workflow and publish it through a snapshot branch

- Status: Superseded by 0041
- Date: 2026-11-22

## Context

ADR 0009 makes a static snapshot the browser's only registry source: spike S4 found that registry.nextflow.io and its bundle CDN send no CORS headers. IO-31 asks for a daily snapshot served with the site, holding a module index (`meta.yml` ports, process or workflow, typed or legacy), per-module bundles, a plugin index and plugin specs; QA-06 caps the module index at 300 kB gzipped. The live registry (measured 2026-11-22) has 2,322 modules and 112 plugins; a single index with ports is 304 kB gzipped, over QA-06. All 2,321 bundles together are 21.6 MB gzipped as JSON. ADR 0002 keeps server work in Actions shipped as static files, and ADR 0017 records build-time hosts. AGENTS.md listed `apps/web/public/registry/**` as generated by a CI job, written before the sizes were known. Research: the [F-501 plan](https://github.com/ewels/nf-builder/blob/cbb24e2/docs/plan/handoff/plan-F-501.md).

## Decision

- **Format v1** (types in `packages/lang-core/src/registry-snapshot.ts`), served at `/registry/`, minified, deterministic, versioned by `format: 1`:
  - `index.json`: per module its name, version, kind, component name, typed (or `null` when `main.nf` couldn't be modelled), description and keywords, plus the plugin index. QA-06 applies to this file.
  - `ports.json`: the `meta.yml` ports of each indexed version, loaded on first need. IO-31's "module index" is read as this pair of files.
  - `modules/<name>/<version>.json`: every file of the registry bundle (non-UTF-8 files as base64) with its verified checksum and pinned `requires`, for each module's latest release and for every pinned dependency version.
  - `plugins/<id>/<version>.json`: description and definitions (config scopes, functions, operators, factories as the plugin spec gives them) of the highest published release whose `requires` admits the pack's pinned Nextflow (26.10.7).
- **Builder:** `tools/registry-snapshot` (`pnpm registry:snapshot`). It may import lang-core and pack entries, an exception to the `tools-standalone` rule (amends ADR 0003's table; a dependency-cruiser rule enforces it), so typed and legacy detection uses the 26.10 pack's parser: the parsed `main.nf` decides kind, component and typed, and disagreements with the registry are reported. `packages/lang-2610` is made erasable (no constructor parameter properties, `erasableSyntaxOnly`) so it runs under plain Node type stripping. Ports come from the registry's normalised metadata with outputs reordered by the bundle's `meta.yml`. `yaml` is a dependency of the tool.
- **Failure policy:** five attempts per request with backoff and the registry's rate-limit headers; a failed module keeps its previous entry or is left out and reported; the build fails if more than 2% of modules and plugins fail or the module count drops below 90% of the previous snapshot's. Only a fully successful run publishes.
- **Check:** `pnpm check:registry` checks QA-06 (warning from 90%) and the snapshot's integrity, locally and against the deployed site.
- **Workflow `Registry snapshot`:** daily at 03:23 UTC, on dispatch, and as a dry run on pull requests touching the tool. The build job is read-only; the publish job (main only) force-pushes a single orphan commit of `registry/**`, with a `netlify.toml` that tells Netlify to skip the branch, to `refs/heads/registry-snapshot`, never to `main`. If the `NETLIFY_BUILD_HOOK` secret exists it triggers a production build and checks the deployed snapshot. The workflow isn't part of "CI green", since it depends on a third party.
- **Serving:** a build-time Vite plugin copies `registry/**` from `REGISTRY_SNAPSHOT_DIR` or, on Netlify, from a shallow clone of the `registry-snapshot` branch (an SSH `REPOSITORY_URL` is rewritten to https). The clone authenticates with `REGISTRY_SNAPSHOT_TOKEN` (a read-only token in Netlify's environment) when set, and reads anonymously otherwise, which works once the repository is public. If the branch is missing or can't be read, the build warns and serves no snapshot rather than failing, so a deploy never depends on it; the palette shows that no snapshot is available (F-502). A failure after a successful read fails the build. The workflow reads the previous snapshot with its own read-only token. Playwright's preview uses the committed golden fixture snapshot.
- **Build-time hosts** (ADR 0017): `registry.nextflow.io`, `public-cr-prod.seqera.io` (bundle download redirect), and `github.com` (git, from the workflow and the Netlify build). The browser's allow-list is unchanged: `/registry/` is same-origin.

## Consequences

- While the repository is private and no token is set, the site serves no snapshot (maintainer issue #31).

- The site serves a registry snapshot no older than a day while `main` moves; with the build hook (maintainer issue #27) it is refreshed daily regardless. The palette shows its age (F-502).
- The repository stays small: the snapshot lives on its own branch, replaced each day.
- A Nextflow pack upgrade changes typed detection and the plugin release choice in one place.

## Alternatives

- Commit the snapshot to `main`: 92 MB of text in the tree with daily bot pushes that bypass PR CI.
- Release assets: the same weight as the branch, plus archive handling.
- Netlify CLI deploys from Actions: needs a token and replaces Netlify's own builds and previews.
- Build the snapshot during each Netlify build: 20 to 45 minutes of registry calls per deploy, previews included.
- One index file without component names and eval item names (264 kB): fits QA-06 today but not for long.
- `node --experimental-transform-types` instead of an erasable pack: an experimental flag in a daily job.
