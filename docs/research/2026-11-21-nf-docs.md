# nf-docs: how it reads pipelines (2026-11-21)

[nf-docs](https://github.com/ewels/nf-docs) generates pipeline API docs (HTML, Markdown, table, JSON, YAML). Read from the `main` branch source and docs on 2026-11-21.

## Inputs it reads

| Source | Used for |
|---|---|
| `README.md` | Pipeline overview |
| `nextflow_schema.json` | Parameters: `description` (short label) and `help_text` (detail), nf-schema format |
| `nextflow.config` | Runtime defaults |
| Language server (hover and symbols) | Processes, workflows, functions, and their Groovydoc comments |
| `meta.yml` | Module metadata: tools, keywords, authors |

## Doc comment format

A Groovydoc block immediately before the declaration:

```groovy
/**
 * Align reads to a reference genome using BWA MEM.
 *
 * Handles both single-end and paired-end reads automatically.
 *
 * @param reads  Tuple of sample ID and FASTQ files
 * @param index  BWA index files
 * @return       Tuple of sample ID and aligned BAM file
 */
```

- Documented tags: `@param` and `@return`.
- The source code also does these things:
  - matches `@param` to process input names, including components of tuple inputs;
  - matches `@return <emit name> <text>` to named outputs (`@return <text>` for an unnamed one);
  - reads the comment from source when the language server's hover leaves it out, which is common for typed processes;
  - accepts a second style, with bullet-list `Inputs:` / `Outputs:` sections in the comment.
- Typed syntax is handled: typed inputs (`name: Type`), destructured tuples, and record outputs.

## Running

- `nf-docs generate <path> --format html|markdown|table|json|yaml --output <dir>`. The default output is `docs/`.
- The language server comes from the latest GitHub release, downloaded automatically, or from `--language-server <jar>`.
- A prek / pre-commit hook is provided. It regenerates on changes to `*.nf`, `nextflow.config`, `nextflow_schema.json`, `meta.yml` and README.
- There are no instructions for GitHub Actions or Pages.
- It needs Python 3.10+ and Java 17+, so it runs in CI, not in the browser.

## Gaps relevant to the builder

nf-docs is Phil's project, so these are upstream suggestions, not blockers:

1. **Workflow take/emit descriptions:** workflow inputs and outputs are built from the signature only. `@param` and `@return` on workflows are not attached to takes and emits, as they are for process inputs and outputs.
2. **Language server version:** there is no option to pick a version (always latest). Passing `--language-server` with a pinned jar works, and is what the builder's workflow will do.
3. **Extra pages:** hand-written Markdown such as `docs/usage.md` and `docs/output.md` (the nf-core convention) isn't included in the generated site.
