# User interface

Mockup: [docs/mockup](../mockup/README.md). Where the mockup and this file disagree, this file wins.

## Layout

| ID | Requirement |
|---|---|
| UX-01 | Header bar with app name, project switcher, save state, New project…, Import, Export, and Nextflow version selector. New project… (which replaces Templates) opens the New project dialog (UX-60) on its last route, and Import opens the same dialog on its Import route, so there is one way to start a project (ADR 0071). The selector lists installed language packs; at launch only `26.10`. |
| UX-02 | Three columns under the header: left (palette or files, 256 px default), centre (tabs plus canvas or editor), right (details, 296 px default). Side columns can be resized and collapsed; widths persist per browser. |
| UX-03 | Status bar: problems count, suggestions count (separate, links to the problems panel), node and channel counts for the active canvas, language version. Problems count errors plus warnings; with a project open both counts are buttons that open the problems panel on their tab; the bar reads "Checking for problems…" before the first result; node and channel counts are hidden on a file tab (ADR 0054). In the problems panel, registry module files are listed after the project's own files, under a "Registry modules" heading with a `registry` tag; counts include them (ADR 0063). With errors, the problems count is drawn in the error colour and keeps its glyph and word (QA-12, QA-13, ADR 0071). |
| UX-04 | Below 1024 px wide (CSS pixels of the window or frame; 1024 px is editable) the app is read-only: canvas and details only, with a note that editing needs a larger screen. A Markdown file tab shows its sanitised preview only; other file tabs, config tabs included, show the note in place of code or form (ADRs 0059, 0061). The palette, Files view, code view, undo and redo, node moves, Auto-layout and project creation, renaming and deletion aren't offered. Commands are refused and nothing is written to the project. Switching projects, opening and switching workflow tabs and the breadcrumb, selection, pan, zoom and fit still work; the take and emit forms aren't offered (ADR 0068). Below 640 px the details sit under the canvas. Narrowing sends a pending code edit first; widening restores the editing controls and each tab's view mode (ADR 0056). |
| UX-05 | Transient messages appear as toasts in one live region (`role="status"`, polite) at the bottom centre, above the status bar: the outcomes of palette, registry and plugin adds, copy, paste and navigation, the popup's refusals while it is closed, export, import and failed saves. At most three show at once and the oldest is dropped. Info and success toasts last 6 s and errors 10 s, paused while hovered or focused; each can be dismissed with its button, or with Escape when focused. Toasts never take focus; a repeated message replaces the last one and is announced again; nothing moves under `prefers-reduced-motion: reduce`. A toast has at most one action, which is also reachable elsewhere. Toasts show above modal dialogs, and messages about a dialog's own fields stay inline. Autosave raises no toast. Persistent states (laying out nodes, content notices, the history notice) stay where they are (ADR 0071). |

## Left column

| ID | Requirement |
|---|---|
| UX-10 | Segmented control switches between **Components** and **Files**. |
| UX-11 | One search box filters every category, generic and registry, by name, description and keywords. |
| UX-12 | Generic categories come first, as collapsible accordions, generated from the language pack's catalogue plus `palette.yaml`: **Processes** (Process, Exec process, Agent, marked preview); **Workflows** (Workflow, Include pipeline); **Params & outputs**; **Channel factories**; **Operators**, grouped (transform, filter, combine, fork, split, reduce, inspect; a group with no modern operator in the pack is left out, as fork and split are in 26.10, ADR 0025); **Types, functions & includes** (record, enum, function, include); **Plugins & config** (ADR 0071). |
| UX-13 | The palette offers modern constructs only (ADR 0007). Nothing invalid for the project's language version appears. Preview features show a `preview` badge. |
| UX-14 | Then a **registry.nextflow.io** section, searched rather than browsed: with an empty query it says "Type to search modules and plugins" and links "Browse registry.nextflow.io" (new tab), listing no rows; with a query it lists the matching Modules (grouped by namespace, `nf-core` first and the rest in name order; rows show the name without its namespace; each list renders 100 rows at a time and loads more as it scrolls; process or workflow marked by icon; typed modules tagged `typed`) and Plugins (ADR 0071). Search covers registry modules (name, description, keywords) and plugins (id, summary) (ADR 0058). A plugin row is added like other items (UX-15) and shows "added" once its plugin is declared (ADR 0065). A refresh button shows the data source (live or snapshot) and its age. The section says when no snapshot is available on the site, when the data couldn't be read (refresh retries), and when a refresh failed (ADR 0050). |
| UX-15 | Items are added by drag and drop onto the canvas, or by keyboard: focus the item, press Enter, and it is placed at the viewport centre. Dropping an operator on an edge inserts it into that edge's chain. A new process or workflow is named `NEW_PROCESS` or `NEW_WORKFLOW` (then `_2`, `_3`, …), called from the open workflow and selected, as one undo step; the canvas keeps its viewport, and focus stays on the palette item. The outcome is shown as a toast (UX-05, ADR 0071). An add that fails partway changes nothing and says why. Items that can't be added yet stay focusable for their description and say so (ADR 0060). |
| UX-16 | The Files view shows the project tree with new file, new folder and upload actions. Registry module folders carry a `registry` tag; files that failed to parse carry an error badge. Dropping files or a zip adds them. The tree lists files before folders. A new folder holds an empty `.gitkeep`. New files and folders are commands, one undo step each. Added files can't be undone and clear the undo history (ADR 0051). One dropped or uploaded zip is imported as in IO-11 and IO-12, with the ignore list editable before confirming; other files are added as text files up to 1 MB, binary files skipped. Registry module folders are found by the pack's include rules, `modules/local/` excepted. A file has failed to parse when it has parse problems; a file only partly parsed without problems carries a neutral badge. `.nf-builder/` is read-only (ADR 0055). A "Configuration" button above the tree opens the root `nextflow.config` in its config tab; it is hidden when that file doesn't exist (ADR 0071). |

## Canvas

| ID | Requirement |
|---|---|
| UX-20 | One canvas per workflow (entry or named). Tabs above the canvas hold open workflows and open files. A file without a workflow opens in a code-only tab with no view-mode toggle (ADR 0054). Code-only file tabs have a close button, and the tab strip is labelled "Open workflows and files" (ADR 0055). Workflow tabs close the same way, with Delete or the close button, except the tab of the default workflow (the entry workflow of `main.nf`, else the first entry workflow), which the project opens with (ADR 0068). Each canvas tab keeps its pan and zoom for the session: switching away and back shows the same viewport without a refit, and a resize doesn't refit it. The kept viewport is cleared when a project opens or closes and when the tab closes (ADR 0071). |
| UX-21 | Node anatomy: kind icon tile, name in monospace, one subtitle line (kind, or registry name), then one row per port. Input ports on the left edge, outputs on the right. A "port labels" toggle hides labels for compact view. A selected call of a workflow or pipeline tells screen readers that pressing Enter again opens it (UX-50, ADR 0068). The canvas controls (Zoom in, Zoom out, Fit view, Port labels, Auto-layout) show tooltips naming the action and its key, on hover after a short delay and at once on keyboard focus; a tooltip stays while the pointer is over it and closes on Escape (WCAG 1.4.13, ADR 0071). |
| UX-22 | Node kinds and colours: process and registry module (green; module shows its registry name), workflow (blue; offset shadow shows it opens), operator chain (amber pill), channel factory (purple), params (purple), output block (pink), take and emit (grey pills), code node (grey, monospace preview of first line), unparsed (grey, error outline). An unresolved callee draws as unparsed, subtitled "not found"; a pipeline draws as a workflow and an agent as a process with its own icon (ADR 0046). |
| UX-23 | Typed processes and workflows carry a small `typed` badge on the top edge. No badge means legacy syntax (ADR 0007). |
| UX-24 | Edges are channels. Queue channels are solid, value channels dashed, plain values dotted; an edge of unknown type is solid, muted and thinner (ADR 0046). Edges touching the selected node are highlighted. Hovering an edge shows its type and source. A type mismatch is drawn red, thicker, with an error mark at its midpoint and the diagnostic on hover and in its accessible name (QA-12). Select an edge (click it, or focus it and press Enter) and press Delete or Backspace to disconnect it; Escape clears the selection (ADR 0064). |
| UX-25 | Connecting: drag from an output port to an input port. Dragging starts only from an output. Invalid targets dim while dragging: targets Connect would refuse dim and can't be dropped on; targets with a known type mismatch dim with a red ring and can be (LA-29). A refused drop is explained in the canvas notices. Connecting creates or rewrites the call's argument (ADR 0004) and keeps the viewport (ADR 0064). |
| UX-26 | Standard canvas controls: pan, zoom, fit, minimap, marquee and shift-click multi-select, delete, copy and paste (within and across projects), undo and redo, auto-layout (ELK) for all or selected nodes. Shift-click adds a node to the selection and Shift-drag draws a marquee; node and edge selection are exclusive. Deleting several nodes is one command and one undo step, and an assignment nothing reads any more becomes a bare call. Copy carries process and workflow calls with their definition files, the project files they include, the rest of an nf-core module or subworkflow directory, and the connections between them; it is held in the app, not the system clipboard, so it works across projects in one tab. Paste is one undo step: an identical file is reused, a different one at the same path refuses the paste, and a process the workflow already calls is offered under an alias (`include { X as X_2 }`) before anything is written (ADR 0067). A context menu on a node, an edge or the pane lists what can be done there: Edit, Code, Open workflow (workflow calls), Copy, Delete and Auto-layout selected on a node; Disconnect on an edge; Paste, Auto-layout all and Fit view on the pane. Actions that don't apply are shown disabled with the reason. In read-only mode it offers only Open workflow, Copy and Fit view. A right-click selects its target first (ADR 0071). |
| UX-27 | View mode toggle per tab: Graph, Split (graph plus live code of the workflow's file, half each), Code. Markdown tabs have Preview, Split and Code and open in Preview; config tabs have Form, Split and Code and open in Form (ADR 0061); other file tabs show code only. G, S and C pick the first, second and third mode of the active tab (ADR 0059). Modes are kept per tab for the session. An edit that doesn't parse keeps its text in the editor, marked with its errors and a status line, while the graph and the saved file stay at the last version that parsed; the draft lasts until the page is reloaded or another project is opened (ADR 0048). The viewport is kept per tab for the session too (UX-20, ADR 0071). |
| UX-28 | Chains expand and collapse in place (ADR 0008). Code nodes show their full text on hover. |

## Details pane (right)

| ID | Requirement |
|---|---|
| UX-30 | A single click selects a node and shows read-only details: name, kind, file, description, inputs and outputs with types and connections, key directives, topics, a short script preview, and diagnostics for that node. Key directives are every directive in source order; the script preview is the first 8 lines; the node's diagnostics are those inside its call or declaration (ADR 0049). With several nodes selected, the pane shows how many, each node's label and kind (selecting it alone), and Copy and Delete; a single node's details also offer Copy and Delete, and with nothing selected and something copied the workflow summary offers "Paste N nodes". In read-only mode Copy stays and Delete and Paste are not shown (ADR 0067). |
| UX-31 | With nothing selected, it shows the open workflow's summary: take, emit, calls, registry modules used (by the folder holding each callee's file, ADR 0055), the share of statements modelled ("165 of 184 statements (89%)", rounded down) and the number of suggestions in the workflow, with a link to the Suggestions tab. The entry workflow, which has no take or emit, lists its parameters and outputs instead (ADRs 0049, 0063), and a link to the project's `nextflow.config` when it has one (ADR 0061). A named workflow's summary offers Add take and Add emit, each an inline form with a name and, for a typed workflow, a type (UX-51, ADR 0068). The default workflow's canvas has a Plugins strip under the breadcrumb with one chip per declared plugin (`id@version`), each opening `nextflow.config` in its config tab; it is hidden when no plugin is declared, shows in read-only, and briefly outlines a newly added plugin's chip (ADR 0071). |
| UX-32 | Header buttons: Edit (opens popup) and Code (opens popup on the Code tab). For registry modules: version, upstream link, "update available" if newer. Edit is enabled for typed processes and disabled with its reason for other nodes. Code is enabled for the same nodes as Edit; in read-only mode neither is rendered (ADRs 0049, 0066, 0069). |

## Edit popup

| ID | Requirement |
|---|---|
| UX-40 | Double-clicking a node (or Enter on a node that is already selected) opens a modal with two tabs: **Configure** (default) and **Code**. Enter on an unselected node only selects it, and Space never opens the modal. Workflow nodes are the exception: double-click, or Enter on the selected node, opens the workflow in a canvas tab (UX-50, ADR 0068). In read-only mode the modal doesn't open, and narrowing below 1024 px closes it and discards its draft (ADR 0066). |
| UX-41 | Configure shows a form for everything the kind supports, built from the catalogue. For a typed process: name, description (doc comment), inputs (name, type, nullable), stage, outputs (name, type, value), topics, directives (add from searchable list), script, stub. Legacy processes get qualifier-based input and output editors. The directive list leaves out deprecated directives and starts each with a default from its catalogue type. Parts the form can't model (`record(...)` and `tuple(...)` inputs, non-string topics, `when:`) are kept as written and shown as code. Registry modules can be edited, with a note that an update will overwrite the changes (ADR 0066). Directive, output and topic values have a mode: Text, written single-quoted, where `$` isn't replaced (a hint says so when the text looks like interpolation), or Expression, written as typed; outputs also have File (`file('…')`, the default for a new output) and Files (`files('…')`). A plain string literal reads as Text, `file` or `files` of one as File or Files, anything else as Expression. An empty type, or an empty value outside Expression, is refused on its field. Placeholders never hold example values; examples go in a visible hint (ADR 0071). |
| UX-42 | There is no control to change a node's kind (ADR 0008). |
| UX-43 | Code shows only that declaration in Monaco, from its doc comment to its trailing comment, with Nextflow highlighting, inline diagnostics and hover help. The text is parsed on its own under the file's feature flags; parse problems show live as markers, and it must stay one declaration of the same kind and style. "Show whole file" switches to the full file, read-only, with the declaration highlighted. "Format" applies canonical formatting (ADR 0005) as one edit the editor can undo; text from Code is otherwise applied as written (ADR 0069). |
| UX-44 | Both tabs edit the same pending state. Apply validates and applies one edit command (one undo step). Cancel discards. If the Code tab doesn't parse, Apply is disabled and the error shown. A rename applies the update, the rename and any module folder move as one group, so it is still one undo step. A refusal changes nothing, keeps the popup open and marks the fields it is about. A form read before the project last changed is refused as stale (ADR 0066). Configure is the source of truth until the Code tab is edited, then the code text is: switching to Configure parses it into the form, and later form edits are redrawn over the code. Apply with a Code edit is one group (renames, `ReplaceDeclaration`, any module folder move); calls follow the inputs by name. Escape with an edited code draft asks "Discard your changes to the code?" with focus on Keep editing; otherwise Escape and Cancel discard at once (ADR 0069). |
| UX-45 | Legacy nodes show a "Migrate to typed" action when a migration is available. It shows a diff and applies only on confirmation (ADR 0007). |
| UX-46 | Every input, output, take and emit row in Configure has a one-line description field. The General section has a Markdown description. These are saved as the doc comment (LA-50), and the details pane shows them next to each port. |

## Workflows and files

| ID | Requirement |
|---|---|
| UX-50 | Opening a workflow node opens or focuses a canvas tab for its definition (aliases resolved; a pipeline call opens its entry workflow). A breadcrumb shows the path from the entry workflow, with back navigation: when the tab was opened from a canvas, the path taken; otherwise the shortest call path from the default workflow, or the workflow alone when it isn't reached. Each ancestor is a button that opens its tab, and the current workflow is marked as the current page. Double-clicking the canvas doesn't zoom. A call that can't be opened (not defined in the project, from a plugin, unparsed, or a process) says why in the canvas notices (ADR 0068). |
| UX-51 | In a workflow canvas, `take` inputs are pills on the left and `emit` outputs pills on the right. Adding, removing or renaming them updates the ports of every call site. A new take is `name: Type` (typed) or `name` (legacy) and leaves each call site unfed: Nextflow reports the missing argument until it is connected. A new emit is `name: Type = null` or `name = null` until connected. Adding a second emit is refused while the workflow has exactly one, because callers read a single emit directly; the emit name `log` is refused because the run fails with it. The entry workflow has no take or emit to add. Removing and renaming come with F-316 (ADR 0068). |
| UX-52 | Opening a file from the Files view uses its editor (`files.md`). Unknown text files open in Monaco. |

## Dialogs

| ID | Requirement |
|---|---|
| UX-60 | New project dialog: name, language version (installed packs only); three routes: Start blank, From a template, Import (GitHub repo with ref and optional token, or zip; the token field arrives with F-402). Shows projects stored in this browser. States that projects live in this browser only. Has "Publish docs to GitHub Pages" (FI-40) and "Generate metro map" (FI-50) checkboxes, both on by default; Publish docs is hidden for a GitHub import (ADR 0057). Publish docs says what it does ("Adds docs/usage.md, docs/output.md and a GitHub Actions workflow that builds documentation with nf-docs and publishes it to GitHub Pages.") and links nf-docs. The header's New project… and Import, the switcher's New project… and the welcome screen open this one dialog. With no project open (a first visit, or after deleting the open project) the centre shows a welcome screen: a heading, that NF Builder builds Nextflow pipelines visually and stores projects in this browser only, New project, From template and Import buttons opening the dialog on those routes, and the projects in this browser, most recently opened first, each with Open (ADR 0071). |
| UX-61 | Import shows a summary (files, skipped, size) before creating the project, on a Review step inside the dialog (Source, then Review with the summary, skipped files, the ignore list, Back and Create), then a report afterwards: parse failures, legacy share, suggestions count. Parse failures are files whose parse status is partial or verbatim, with the declarations kept as text; the legacy share is legacy processes and workflows over all modelled processes and workflows, as counts and a percentage; suggestions are diagnostics of severity `suggestion` at import time. The report is session-only (ADR 0057). Skip reasons are in plain words with one sentence of help each. GitHub errors offer the action that helps: Retry (network, rate limit, refused, download, incomplete), Open on GitHub and Change ref (not found, no such ref), Add ignore patterns (truncated tree, limit breaches), or Report a problem (unknown errors), which links the nf-builder issues page with no project data in the URL (ADR 0071). |
| UX-62 | Export dialog: zip of the project, with a checkbox to include the layout sidecar (on by default). It warns about paths that differ only by case and files that are also folders, still exports, and notes that files skipped at import are missing (ADR 0062). |

| UX-70 | Every action reachable by mouse is reachable by keyboard. Minimum shortcuts: search (`/`), add focused palette item (Enter), delete (Delete/Backspace; the selected edge, else the selected nodes), copy and paste nodes (Ctrl+C and Ctrl+V; ⌘C and ⌘V on Apple platforms; not in text fields, code editors or dialogs, and copy yields to selected text, ADR 0067), undo and redo (Ctrl+Z, Ctrl+Shift+Z or Ctrl+Y; ⌘Z and ⇧⌘Z on Apple platforms; text fields and code editors keep their own undo, ADR 0051), open popup or, on a selected workflow call, its tab (Enter), close popup (Esc), fit (`F`), auto-layout (`L`), switch view mode (`G`, `S`, `C`), context menu on the focused node, edge or pane (Shift+F10 or the ContextMenu key; arrow keys, Home and End move, Enter or Space runs, Escape closes and returns focus, ADR 0071). |
